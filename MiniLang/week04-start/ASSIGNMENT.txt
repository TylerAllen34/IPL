WEEK 04 — Declare names and manage block scopes

EXERCISE FOCUS
We will connect declaration identity, initialization order and block scope.
You will implement one coherent resolver protocol using the supplied AST.

GOAL AND LECTURE CONNECTION
Give each declaration a distinct identity in its current scope, reject
same-scope duplicates, and permit reads only after its initializer resolves.
Enter and leave one name table for each nested block. Explain shadowing
without confusing compiler metadata with runtime values.
Work in the project folder you received. Everything needed is included here.

STARTING POINT: PROVIDED INFRASTRUCTURE AND LIMITS
Identifier scanning, variable/assignment/block parsing, AST nodes and
formatting, C++ generation and runtime storage are supplied. The resolver's

The name-use and assignment visitors are provided; literals need no binding.
You complete declare(), define(), and the VarStatement and BlockStatement

Each Binding has an id and a defined flag. scopes_ is a vector of maps;
scopes_.back() is current. next_symbol_ supplies the next declaration ID.
Lookup deliberately searches ONLY the current scope, even in the solution.
An inner declaration may shadow an outer name, but an outer-only name is
unavailable inside a nested block. Keep this temporary boundary intact.
Operators, branches, loops and general calls are absent. Lowering is identity.

YOUR C++ TASK — FOUR CONNECTED PARTS IN src/resolver.cpp
Keep the existing signatures and node-dispatch conditions. Replace the TODO
bodies below; remove placeholder throws and both (void) placeholder lines.
Do not change resolveName(), the AST, parser, code generator or runtime.

1. Resolver::declare(VarStatement &variable)
   Take a mutable reference to the current scope and copy next_symbol_ as id.
   Attempt to insert variable.name with Binding{id, false} into that map.
   If insertion fails, throw a resolve CompileError with source_.name(),
   variable.name_span and: duplicate variable '<name>' in the same scope
   Substitute the actual name. Do not search outer maps for duplicates.
   After successful insertion, set variable.resolved_id to id, then increment
   next_symbol_. Do not reset the counter on block entry or allocate IDs for
   uses. Each distinct declaration must retain a distinct identity.

2. Resolver::define(const std::string &name)
   Find the existing name in the current map and set its defined flag to true.
   Use the binding inserted by declare(); do not create another binding or ID.

3. VarStatement branch in Resolver::resolveStatement(Statement &statement)
   Call declare(*variable), resolveExpression(variable->initializer), then
   define(variable->name), in that order; return from the handled branch.
   If the initializer fails, define() is never reached. Declaring first lets
   the supplied lookup reject a read of the new name in its own initializer.

4. BlockStatement branch in Resolver::resolveStatement(Statement &statement)
   Call beginScope(), resolveStatements(block->statements), then endScope();
   return from the handled branch. Enter before the first child and leave
   only after successful ordered traversal. Nested blocks reuse this visitor.

One block means one map, not one map per statement. Reusing the parent map
would confuse shadowing with duplication; forgetting to pop leaks names.
On an error compilation stops and the resolver is discarded. Error recovery
and a persistent symbol service are outside this exercise.
